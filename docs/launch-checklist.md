## 4. Merge (needs explicit approval)

- [ ] Use a **merge commit** (not squash) so the commit history still shows the work as it was done (an assignment requirement).
- [ ] Merging to `main` triggers `pages.yml`, which deploys the site. The next daily run will also redeploy.
- [ ] Do **not** merge while a scheduled run is in progress (check `gh run list`), to avoid a push race on `data/`.
      The daily workflow does `git pull --rebase --autostash` before `git push` and has a `concurrency` group, so a merge landing between runs is safe; confirm that file is unchanged after the merge.

      `portfolio.html`, `platform.html`, `manifest.webmanifest`, `sw.js`, `data/history.csv`, `data/status.json`.
- [ ] Open the live site in a fresh browser profile and in one that has the **old** service worker installed: the cache upgrades

- [ ] Run `scripts/browser-audit/regression.js` and `required-pages.js` against the live URL (service workers must not be blocked
      for the offline check).
- [ ] Install the app from the browser on a computer and a phone; open it offline.
- [ ] Next scheduled run completes, opens its Issue, closes the previous one, and the live site updates.
- [ ] No console errors on any page; 404s only for `explorer/sec/company/*` (none expected: the placeholder index is empty).

## 6. Going live with real SEC data (separate approval; needs the mailbox)

1. Create the mailbox; add the repository secret `SEC_USER_AGENT` = `CreditScope educational project <mailbox>`.
2. Copy `docs/fundamentals-workflow.example.yml` to `.github/workflows/fundamentals.yml` (manual trigger only, builds an artifact,
   commits nothing).
3. Run it for `AAPL,MSFT,WMT,JPM` first. Download the artifact; confirm sizes are small (each company file < 60 KB).
4. `python -m fundamentals verify <TICKER> --sheet sheet.md` for each (needs the same secret locally), then complete
   `sheet.md` by hand against the filings (procedure: `docs/sec-edgar-plan.md`).
5. Review `coverage` and `checks` for each company (banks such as JPM will legitimately lack gross profit and operating income).
6. Only after the human verification passes: commit `explorer/sec/` (compact JSON only; never raw filings), review the diff, and
   deploy through the normal merge path. Update `reducerVersion` notes if the rules changed.
7. Widen the universe (`fundamentals/universe.txt`) gradually; the SEC allows 10 requests/second and the client uses 5.

## 7. Rollback

- Revert the merge commit on `main` (`git revert -m 1 <merge>`); `pages.yml` redeploys the previous site. Data files are
  unaffected because the branch never writes `data/`.
- If a service-worker problem appears, bump `VERSION` in `sw.js` (clients drop old caches on activate).
- The assignment pipeline is independent of all of this; a rollback never touches `data/raw`, `history.csv` or the Issues.
